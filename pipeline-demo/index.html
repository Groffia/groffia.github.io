Multi-source data pipeline

The pipeline collects records from four sources twice a day, drops records that fail the rules, merges duplicates, skips anything already shown, then scores, tiers and explains every record that's left. The real tool runs as Claude Code skills on a schedule and writes to a database-backed web app.

This page replays one sample day. Every supplier and price is made up for Tamsworth Health, a fictional health system buying clinic supplies. The real tool runs on private data.

How it's built

Claude Code does the steps. The rules decide.

  1. Scheduled runs. A scheduled task starts the pipeline at 6am and 1pm every day, with no manual trigger.
  2. Collect through the browser. A custom Claude Code skill reads each source in a real browser over MCP, then pulls the same fields from every record.
  3. Filter, then merge. Any rule fail drops the record. Records with the same normalized key are merged, keeping every source they came from.
  4. Seen log. Each listed record's key is appended to a log, so a later run never shows it twice.
  5. Score with reasons. Want (0–10) and Match (0–5) follow the written rules, and each row carries a one-line reason and its gaps.
  6. Database-backed board. Results go to a ranked file and a small web app whose status (new, shortlist, skip) lives in a database.
